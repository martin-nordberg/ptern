# Ptern Playground — TypeScript Engine Migration Plan

**Status:** Done — all phases (0–4) implemented and verified; kept as a historical record, matching `typescript-port.md`/`kotlin-port.md`.
**Date:** 2026-08-09

---

## 1. Goal

Replace `ptern-playground`'s pattern engine — currently the transpiled output of `ptern-gleam` — with `ptern-typescript` (`@ptern/tern`), consumed as a local workspace dependency. When this is complete:

- `ptern-playground` has **no dependency on `ptern-gleam`** anywhere: no `gleam build` invocation, no copied Gleam/`gleam_stdlib` JavaScript, no Gleam-shaped runtime values (`Ok`/`Error`/`Some`/`None`/Gleam records) touched anywhere in playground code.
- `@ptern/tern` is pulled from the local monorepo workspace (`ptern-typescript/`), not from the npm registry.
- The playground's dev/build pipeline builds `ptern-typescript` and makes its build output available to the playground, mirroring what `scripts/copy-gleam.sh` does today for the Gleam edition.
- The playground's UI, layout, and behavior are unchanged — this is an engine swap, not a feature change. `documentation/ideas/playground.md` (the feature spec) remains accurate for everything except the engine-integration details in its §2, which this document supersedes.

This is a smaller effort than `typescript-port.md` or `kotlin-port.md`: `ptern-typescript` already exists, is fixture-tested, and its public API surface (`compile`, `Ptern` methods, `format`, error types) already covers everything the playground needs, with three small gaps called out in §3.

## 2. Current State (Gleam-based)

Summarized from `documentation/ideas/playground.md` §2 and the current source:

- `ptern-playground/scripts/copy-gleam.sh` runs `gleam build` in `ptern-gleam/`, then copies `ptern-gleam/build/dev/javascript/{ptern,gleam_stdlib,gleam_version,prelude.mjs}` into `ptern-playground/src/ptern/`.
- `package.json` scripts (`dev`, `build`) run this script before `vite`/`vite build`.
- `src/ptern/api.ts` is the **only** file that touches the engine. It imports the copied Gleam JS modules directly (`./ptern/ptern.mjs`, `./gleam_stdlib/gleam/dict.mjs`, `./prelude.mjs`, `./ptern/formatter/formatter.mjs`) and exposes a typed, idiomatic TypeScript facade: plain functions taking a `Ptern` as the first argument, `{ ok, ... }`-shaped results instead of exceptions, and camelCase field names.
- Every other file (`store.ts`, `App.tsx`, `EditorPanel.tsx`, `TabContent.tsx`, `TabBar.tsx`, `TestPanel.tsx`, `FormatOptionsModal.tsx`) imports only from `./ptern/api` (or `../ptern/api`) and never touches the engine directly.
- `.gitignore` excludes the copied Gleam output (`src/ptern/ptern/`, `src/ptern/gleam_stdlib/`, `src/ptern/gleam_version*`, `src/ptern/prelude.mjs`) since it's regenerated by the copy script.

This existing structure is good news for the migration: **`api.ts` is already the seam**. The plan below keeps it that seam — only `api.ts`'s internals change; everything downstream of it is untouched.

## 3. Required Upstream Changes to `ptern-typescript`

`ptern-typescript`'s public API (`ptern-typescript/src/index.ts`, documented in `ptern-typescript/doc/user-guide.md`) already covers matching, replacement, substitution, length metadata, and formatting. Three small additions are needed before it can fully replace the Gleam edition for the playground's needs:

### 3.1 Expose `isSubstitutable`, the compiled regex source, and its flags

The playground's "Show regex" panel (`documentation/ideas/playground.md` §5.3) and the Substitution-mode gate (§7.1) currently read `ptern.is_substitutable`, `ptern.source`, and `ptern.flags` directly off the compiled Gleam record. This works today only because Gleam's `pub opaque type Ptern` encapsulation is a **compile-time-only** concept in Gleam — the compiled JavaScript object has no runtime privacy, so `api.ts` reaches past it. That is not an intentional part of Gleam's public API; it is a leak the playground has been relying on.

`ptern-typescript`'s `Ptern` class uses real JavaScript private fields (`#isSubstitutable`, `#flags`; the compiled regex source string isn't even stored — the constructor parameter is named `_source` and discarded). There is no way to reach these from outside the class, by design. So this needs a **real, documented, public API addition**, not a workaround:

```ts
// ptern-typescript/src/index.ts, inside class Ptern

get isSubstitutable(): boolean {
  return this.#isSubstitutable;
}

get regexSource(): string {
  return this.#source;   // needs to actually be stored — see below
}

get regexFlags(): string {
  return this.#flags;
}
```

This requires:
- Adding a `#source: string` private field, storing the `source` constructor argument (currently discarded as `_source`) instead of throwing it away.
- Three new one-line getters as above (naming: `regexSource`/`regexFlags` rather than bare `source`/`flags`, to avoid any ambiguity with the compile-time `source` argument name and to read clearly at call sites like `ptern.regexSource`).
- A unit test (e.g. in `ptern-typescript/test/api/`) asserting `compile("...").regexSource`/`.regexFlags` are non-empty strings and that `.isSubstitutable` reflects the `!substitutable` annotation.
- A short addition to `ptern-typescript/doc/user-guide.md` — a small note near "Length Metadata" or a new "Inspecting a Compiled Ptern" subsection documenting `regexSource`, `regexFlags`, and `isSubstitutable` as intentional, stable, public introspection API (this is genuinely useful beyond the playground — e.g. for debugging or logging in any consumer).

This is upstream, package-level work on `ptern-typescript` itself, done once, before the playground migration begins (§11, Phase 0).

### 3.2 No other gaps

Everything else the playground needs is already public and already matches or trivially maps onto what `api.ts` exposes today (full mapping in §7). `matchNextIn`/`replaceNextIn` exist on `ptern-typescript`'s `Ptern` class but — per `playground.md` §9.10–9.11 — are intentionally not used by the playground; no gap there.

## 4. Decisions

| Topic | Decision | Rationale |
|---|---|---|
| Dependency source | Local workspace (Bun workspaces), not the npm registry | The instruction is explicit; also avoids a publish step just to consume an in-repo package during development. |
| `api.ts`'s role | Keep it as the seam; rewrite its internals only | Every other playground file already goes through `api.ts`. Preserving its exported function names, parameter shapes, and return-value shapes means `store.ts`, `EditorPanel.tsx`, `TabContent.tsx`, and `FormatOptionsModal.tsx` need **zero changes**. |
| Error handling style at the seam | Keep `api.ts`'s current `{ ok: true, ... } \| { ok: false, error }`-style returns for `compilePtern`/`formatPtern`/replace/substitute | `ptern-typescript` itself throws (`PternCompileError` etc., per `typescript-port.md`'s decision), but the playground UI is written around non-throwing result values today. `api.ts` wraps each throwing call in `try/catch` and converts back to the existing shape — this is a few lines per function and avoids touching UI code at all. |
| "Copying resources" | Handled by the package manager (workspace symlink), not a shell script | `ptern-typescript` is a real npm-shaped package (`@ptern/tern`, with `exports`/`types`/`files` in its `package.json`) — unlike the Gleam edition, which has no `package.json` at all and must be manually copied file-by-file. A workspace dependency plus `bun install` gives `ptern-playground/node_modules/@ptern/tern` as a symlink to `ptern-typescript/` for free; no manual copy step is needed or wanted. The playground's build/dev scripts still need to **build** `ptern-typescript` first (its `dist/` is what the `exports` field points to), replacing `copy-gleam.sh`'s `gleam build` step with `bun run build` in `ptern-typescript`. |
| Workspace scope | Root-level `package.json` with `"workspaces": ["ptern-typescript", "ptern-playground"]` | Only these two are Bun/npm-managed JS projects; `ptern-gleam` (Gleam toolchain) and `ptern-kotlin` (Gradle/JVM) are unaffected and excluded. This is a new file at the repo root — flagged explicitly since it's a visible structural change (see §5). |
| `ptern-typescript` build target | Verify `bun build --target node` output works unmodified under Vite; switch to `--target browser` (or drop `--target`) if not | The library has zero Node built-in dependencies (verified: no `node:` imports, no `fs`/`path`/`process` usage), so this is expected to be a non-issue, but should be confirmed rather than assumed (§11, Phase 2). |

## 5. Workspace and Build Architecture

### 5.1 New root `package.json`

```json
{
  "private": true,
  "workspaces": [
    "ptern-typescript",
    "ptern-playground"
  ]
}
```

No root lockfile policy change is forced by this — running `bun install` from the repo root will produce a root `bun.lock` covering both workspace packages and symlink `ptern-playground/node_modules/@ptern/tern` → `../../../ptern-typescript`. The existing per-package `bun.lock` files in `ptern-typescript/` and `ptern-playground/` are superseded by the root lockfile and should be removed once the workspace is set up (documented as a one-time migration step, §11 Phase 1).

`ptern-typescript`'s and `ptern-playground`'s own scripts (`bun test`, `bun run build`, `bun run dev`, etc.) continue to work unchanged when run from within their own directories — workspaces are additive for cross-package resolution and don't change how a package's own scripts execute.

### 5.2 `ptern-playground/package.json` changes

```jsonc
{
  // ...
  "scripts": {
    "build-engine": "bun run --cwd ../ptern-typescript build",
    "dev": "bun run build-engine && vite",
    "build": "bun run build-engine && tsc -b && vite build",
    "preview": "vite preview"
  },
  "dependencies": {
    "@ptern/tern": "workspace:*",
    "@tailwindcss/vite": "^4.3.0",
    "solid-js": "^1.9.12",
    "tailwindcss": "^4.3.0"
  }
  // devDependencies unchanged
}
```

`scripts/copy-gleam.sh` is deleted; `copy-gleam` script entry is removed. The `build-engine` script name is deliberately generic (not `copy-ptern-ts`) since, per §4, there is no copy step anymore — it only builds `ptern-typescript`'s `dist/`.

### 5.3 `ptern-typescript/package.json` / `.gitignore`

No changes needed to `ptern-typescript/package.json` itself — its existing `build` script (`bun build src/index.ts --outdir dist --target node && tsc -p tsconfig.build.json --emitDeclarationOnly`) already produces exactly what `exports: { ".": "./dist/index.js" }` and `types: "./dist/index.d.ts"` promise.

`ptern-typescript` currently has **no `.gitignore` at all**, and the repo-root `.gitignore` only excludes `build/` (matching Gleam's output directory) and `node_modules/` — it does not exclude `dist/`. Add a `ptern-typescript/.gitignore`:

```
dist/
node_modules/
```

(`node_modules/` is redundant with the root `.gitignore` once workspaces are set up, but harmless to keep for anyone running `bun install` directly inside `ptern-typescript/`.)

### 5.4 `ptern-playground/.gitignore`

Remove the now-unused Gleam-copy entries:

```diff
- # Generated Gleam output (rebuilt by scripts/copy-gleam.sh)
- src/ptern/ptern/
- src/ptern/gleam_stdlib/
- src/ptern/gleam_version
- src/ptern/gleam_version/
- src/ptern/prelude.mjs
```

Nothing replaces them — `@ptern/tern`'s build output lives in `ptern-typescript/dist/` (ignored there per §5.3), not copied into `ptern-playground/src/`.

### 5.5 Vite / TypeScript resolution

- Vite (esbuild-based dep pre-bundling) resolves symlinked workspace packages by default; no `vite.config.ts` changes are expected to be necessary. If `optimizeDeps` fails to pick up changes to `@ptern/tern` during `vite dev` (a known class of monorepo-symlink quirk), the fallback is `optimizeDeps.include: ['@ptern/tern']` or `resolve.preserveSymlinks: true` — call this out during Phase 2 verification (§11) rather than adding it preemptively.
- `tsconfig.app.json`'s `moduleResolution: "bundler"` resolves `@ptern/tern`'s `types` field (`./dist/index.d.ts`) the same way it resolves any other `node_modules` package — no path mapping needed, unlike the current setup where Gleam's output has no `.d.ts` at all (the whole reason `api.ts` types everything as `Any` internally today).
- First-time setup (fresh clone) requires `ptern-typescript/dist/` to exist before `tsc -b`/editor tooling can resolve `@ptern/tern`'s types. `bun run build-engine` (§5.2) covers `dev`/`build`, but note this explicitly in `ptern-playground/README.md` for anyone opening the project in an editor before running either script.

## 6. `src/ptern/api.ts` Rewrite

### 6.1 Imports

```ts
// Before
import * as gleamPtern from './ptern/ptern.mjs'
import { insert as dictInsert, new$ as dictNew, to_list as dictToList } from './gleam_stdlib/gleam/dict.mjs'
import { toList as gleamToList } from './prelude.mjs'
import { FormatOptions$FormatOptions as makeGleamFormatOptions } from './ptern/formatter/formatter.mjs'

// After
import {
  compile as pternCompile,
  format as pternFormat,
  PternCompileError, PternReplacementError, PternSubstitutionError, PternFormatError,
  type Ptern as EnginePtern,
  type ReplacementMap,
  type FormatOptions as EngineFormatOptions,
} from '@ptern/tern'
```

All the Gleam-runtime plumbing (`isOk`, `gleamListToArray`, `gleamDictToRecord`, `jsToGleamReplacementDict`, `convertOccurrence`'s `Option`-unwrapping) is deleted outright — `ptern-typescript` already returns/throws plain JS values (`string[]`, `Record<string, string>`, `T | null`, thrown `Error` subclasses), so there is nothing to convert at that level.

### 6.2 Public types — kept, bodies simplified

`api.ts`'s exported type aliases (`Ptern`, `CompileError`, `FormatOptions`, `MatchOccurrence`, `CaptureInput`, `ReplacementError`, `SubstitutionError`) are **kept with their current shapes and kind-string values** so downstream files don't change. Concretely:

- `export type Ptern = EnginePtern` (was `Any`).
- `FormatOptions` and `MatchOccurrence` are already structurally identical to `ptern-typescript`'s versions (same field names, same casing) — these become direct re-exports/aliases rather than hand-written duplicates.
- `CompileError`, `ReplacementError`, `SubstitutionError` keep their existing shorter `kind` strings (`'lex'`, `'invalid'`, `'missing'`, etc.) — `api.ts`'s conversion functions translate `ptern-typescript`'s `kind` strings into these, per the mapping tables below. (An alternative is to drop `api.ts`'s own kind strings and adopt `ptern-typescript`'s directly, which would be *slightly* less code in `api.ts` but requires updating the `switch` statements in `TabContent.tsx` — rejected per the "zero UI changes" decision in §4.)

### 6.3 Function-by-function mapping

| `api.ts` export | Old (Gleam) call | New (`@ptern/tern`) call |
|---|---|---|
| `compilePtern(source)` | `gleamPtern.compile(source)` → `Result` | `try { new EnginePtern... } catch (e) { if (e instanceof PternCompileError) ... }` — see §6.4 |
| `getDefaultFormatOptions()` | `gleamPtern.default_format_options()` | `{ lineWidth: 80, compact: false, aligned: true, reordered: false }` (no `defaultFormatOptions` export exists — see `ptern-typescript/doc/user-guide.md`'s "FormatOptions" section; hardcode the literal default object, matching what that guide documents) |
| `formatPtern(source, options)` | `gleamPtern.format(source, gleamOpts)` → `Result` | `try { return pternFormat(source, options) } catch { return null }` |
| `matchesAllOf(p, s)` etc. (4 boolean fns) | `gleamPtern.matches_all_of(p, s)` | `p.matchesAllOf(s)` |
| `matchAllOf(p, s)` etc. (4 single-occurrence fns) | `unwrapOccurrenceOption(gleamPtern.match_all_of(p, s))` | `p.matchAllOf(s)` (already returns `MatchOccurrence \| null`) |
| `matchAllIn(p, s)` | `gleamListToArray(...).map(convertOccurrence)` | `p.matchAllIn(s)` (already `MatchOccurrence[]`) |
| `replaceAllOf(p, s, captures)` etc. (5 fns) | `runReplacement(gleamPtern.replace_*, ...)` | `try { return p.replace*(s, captures as ReplacementMap) } catch (e) { if (e instanceof PternReplacementError) return convertReplacementError(e.replacementError) }` |
| `substitute(p, captures)` | `gleamPtern.substitute(...)` → `Result` | `try { return p.substitute(captures as ReplacementMap) } catch (e) { if (e instanceof PternSubstitutionError) return convertSubstitutionError(e.substitutionError) }` |
| `getMinLength(p)` | `gleamPtern.min_length(p)` | `p.minLength()` |
| `getMaxLength(p)` | unwrap `gleamPtern.max_length(p)` `Option` | `p.maxLength()` (already `number \| null`) |
| `isSubstitutable(p)` | `(p).is_substitutable` (raw field access) | `p.isSubstitutable()` (new method, §3.1/Phase 0 — implemented as a method, not a property getter, to match `minLength()`/`maxLength()`'s existing convention) |
| `getRegexSource(p)` | `(p).source` (raw field access) | `p.regexSource()` (new method, §3.1/Phase 0) |
| `getRegexFlags(p)` | `(p).flags` (raw field access) | `p.regexFlags()` (new method, §3.1/Phase 0) |

`CaptureInput` (`Record<string, string | string[]>`) is already exactly the shape `ptern-typescript`'s `ReplacementMap` wants — no conversion function (`jsToGleamReplacementDict`) is needed at all; `captures` is passed straight through.

### 6.4 Error conversion — replacing the `constructor.name` switches

The three `format*Error` functions and `convert*Error` functions currently pattern-match on Gleam's compiled-record `constructor.name` (PascalCase, e.g. `'UndefinedReference'`, `'InvalidRangeEndpoint'`) with positional field access (`inner[0]`, `e.name`, `e.branch_a`). These are replaced with `switch` statements on `ptern-typescript`'s `kind` string fields (camelCase, named properties) — no `constructor.name` introspection anywhere, since these are plain discriminated-union objects, not opaque runtime records.

**`formatLexError`** (`LexError["kind"]` → same 3 cases):

| Gleam constructor name | `ptern-typescript` `kind` |
|---|---|
| `UnexpectedCharacter` | `unexpectedCharacter` (field: `char`, was `inner[0]`) |
| `UnterminatedString` | `unterminatedString` |
| `InlineComment` | `inlineComment` |

**`formatParseError`** (`ParseError["kind"]`):

| Gleam constructor name | `ptern-typescript` `kind` |
|---|---|
| `UnexpectedToken` | `unexpectedToken` (fields: `expected`, `got` — same names) |
| `UnexpectedEndOfInput` | `unexpectedEndOfInput` |
| *(not handled today)* | `orphanedComment`, `trailingComment` — reachable from `compile()` (a misplaced `#` doc comment triggers these in `ptern-typescript/src/parser/parser.ts`, not just from the formatter path); `api.ts`'s Gleam-era `formatParseError` never handled the equivalent Gleam variants either, so this is a small genuine improvement, not just a straight port — add both cases so the `switch` is exhaustive |

**`formatSemanticError`** (`SemanticError["kind"]` — direct 1:1 rename, PascalCase constructor → camelCase `kind`, `branch_a`/`branch_b` → `branchA`/`branchB`):

`UndefinedReference`→`undefinedReference`, `DuplicateDefinition`→`duplicateDefinition`, `CircularDefinition`→`circularDefinition` (field `names: string[]`, was a Gleam list needing `gleamListToArray`), `CaptureDefinitionConflict`→`captureDefinitionConflict`, `InvalidRangeEndpoint`→`invalidRangeEndpoint`, `InvertedRange`→`invertedRange`, `InvertedRepetitionBounds`→`invertedRepetitionBounds`, `InvalidExclusionOperand`→`invalidExclusionOperand`, `UnknownAnnotation`→`unknownAnnotation`, `DuplicateAnnotation`→`duplicateAnnotation`, `InvalidEscapeSequence`→`invalidEscapeSequence`, `UnknownPositionAssertion`→`unknownPositionAssertion`, `PositionAssertionInRepetition`→`positionAssertionInRepetition`, `SubstitutionsIgnoreMatchingWithoutSubstitutable`→`substitutionsIgnoreMatchingWithoutSubstitutable`, `NotSubstitutableBody`→`notSubstitutableBody`, `BoundedRepetitionNeedsCapture`→`boundedRepetitionNeedsCapture`, `EmptyLiteral`→`emptyLiteral`, `EmptyCharacterSet`→`emptyCharacterSet`, `AmbiguousRepetitionAdjacency`→`ambiguousRepetitionAdjacency` (fields `branchA`/`branchB`), `AmbiguousRepetitionBody`→`ambiguousRepetitionBody`, `AmbiguousAdjacentRepetition`→`ambiguousAdjacentRepetition`, `FewestOnExactRepetition`→`fewestOnExactRepetition`, `UnusedDefinition`→`unusedDefinition`.

(`DuplicateCapture` is filtered out before reaching user-facing error lists in every edition per `CLAUDE.md` — no case needed, same as today.)

**`convertReplacementError`** (`api.ts`'s `ReplacementError["kind"]` ← `ptern-typescript`'s `ReplacementError["kind"]`):

| `api.ts` kind (unchanged) | `ptern-typescript` kind | fields |
|---|---|---|
| `'invalid'` | `invalidReplacementValue` | `captureName`, `value` (same names) |
| `'wrongType'` | `wrongReplacementType` | `captureName` |
| `'lengthMismatch'` | `arrayLengthMismatch` | `captureName`, `provided`, `actual` |
| `'duplicateRepetition'` | `duplicateRepetitionCapture` | `captureName` |

**`convertSubstitutionError`** (`api.ts`'s `SubstitutionError["kind"]` ← `ptern-typescript`'s `SubstitutionError["kind"]`):

| `api.ts` kind (unchanged) | `ptern-typescript` kind | fields |
|---|---|---|
| `'notSubstitutable'` | `notSubstitutable` | — |
| `'missing'` | `missingCapture` | `name` |
| `'mismatch'` | `captureMismatch` | `name` (`value` also present upstream; `api.ts`'s `SubstitutionError` type doesn't carry it today — keep as-is, matching current behavior) |
| `'lengthError'` | `arrayLengthError` | `name`, `length`, `min`, `max` (note: `max` is `number \| null` upstream; `api.ts`'s current type has `max: number`, a pre-existing narrowing that should become `number \| null` to be correct — this is a small, harmless type-only fix) |
| `'noMatchingBranch'` | `noMatchingBranch` | — |

### 6.5 `compilePtern` in full (illustrative sketch, not final code)

```ts
export function compilePtern(source: string): { ok: true; ptern: Ptern } | { ok: false; error: CompileError } {
  try {
    return { ok: true, ptern: pternCompile(source) }
  } catch (e) {
    if (!(e instanceof PternCompileError)) throw e   // programmer error — don't swallow
    const err = e.compileError
    switch (err.kind) {
      case 'lexError': return { ok: false, error: { kind: 'lex', message: formatLexError(err.error) } }
      case 'parseError': return { ok: false, error: { kind: 'parse', message: formatParseError(err.error) } }
      case 'semanticErrors': return { ok: false, error: { kind: 'semantic', messages: err.errors.map(formatSemanticError) } }
    }
  }
}
```

The `if (!(e instanceof X)) throw e` re-throw guard is used in every wrapper function — a genuinely unexpected exception (a bug) should surface as an unhandled error during development, not be silently absorbed into a generic error state.

## 9. Testing / Verification Plan

No automated test suite exists for `ptern-playground` today (UI-only, manual-QA project per its current structure). Verification is a manual pass through `documentation/ideas/playground.md`'s feature list after the migration, using the same example patterns already described there:

1. **Compile status** (§5.2): valid pattern → green "Successful Compilation"; each error class (lex, parse, semantic — trigger with e.g. `''`, an unterminated literal, and `%Any * 3 fewest`) → red message text, and confirm the *wording* is still sensible (it will differ slightly from Gleam's messages since `formatLexError`/`formatParseError`/`formatSemanticError` are rewritten, not literally ported character-for-character).
2. **Pattern metadata** (§5.3): min/max length display correctly for a bounded and an unbounded pattern; "Show regex" panel renders a non-empty `/source/flags` string (exercises the new `regexSource`/`regexFlags` getters from §3.1).
